# Requisitos Funcionais

Com base na análise do documento de elicitação "Levantamento Elicitação", foram identificados os seguintes requisitos funcionais (o que o sistema deve fazer):

*   **RF01 (Catálogo de Eventos):** O sistema deve exibir um catálogo centralizado para que os participantes visualizem todos os eventos disponíveis.
*   **RF02 (Inscrição em Múltiplas Atividades):** O sistema deve permitir que um participante se inscreva em múltiplos workshops/eventos ocorrendo no mesmo dia.
*   **RF03 (Emissão de Comprovante):** O sistema deve gerar e enviar (ou disponibilizar) um comprovante de inscrição logo após a efetivação da inscrição pelo participante.
*   **RF04 (Cancelamento Self-Service):** O sistema deve permitir que o participante solicite o cancelamento da sua própria inscrição de forma autônoma.
*   **RF05 (Emissão de Certificados):** O sistema deve permitir que os participantes emitam seus certificados após a conclusão do evento.
*   **RF06 (Controle de Vagas):** O sistema deve controlar automaticamente a quantidade de vagas disponíveis em cada evento, reduzindo o limite conforme as inscrições ocorrem.
*   **RF07 (Lista de Espera):** O sistema deve permitir a entrada em uma lista de espera quando as vagas de um evento se esgotarem.
*   **RF08 (Dashboard em Tempo Real):** O sistema deve apresentar aos organizadores a quantidade de inscritos em cada evento em tempo real.
*   **RF09 (Eventos Pagos e Gratuitos):** O sistema deve suportar o cadastro e processamento de inscrições tanto para eventos gratuitos quanto para eventos que exigem pagamento.
*   **RF10 (Validação de Pagamento):** O sistema deve permitir que inscrições pendentes aguardem a confirmação do pagamento para liberação definitiva da vaga (integração ou controle por parte da equipe financeira).
*   **RF11 (Listagem para Palestrantes):** O sistema deve permitir aos palestrantes a consulta da lista de participantes inscritos especificamente em suas atividades.
*   **RF12 (Configuração de Cancelamento):** O sistema deve permitir aos organizadores configurar, por evento, se o cancelamento de inscrição é permitido ou não.
*   **RF13 (Gestão de Eventos / CRUD):** O sistema deve fornecer uma interface para que os organizadores possam criar, editar e excluir eventos/workshops no catálogo.
*   **RF14 (Gestão de Participantes):** O sistema deve permitir aos organizadores visualizar a lista completa de inscritos de qualquer evento e intervir manualmente (ex: remover participante, aprovar inscrição).
